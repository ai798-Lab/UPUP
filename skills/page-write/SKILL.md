# page-write · 写一段能被整段摘走的内容

它不凭空写。先把竞品在这个题目上写得最好的那几页抓下来读一遍，看清楚人家给了什么事实、
用了什么结构，然后写一块**你有、他们没有**的东西。写完自己跑一遍机械闸，不达标就改内容再跑。

**产出的是草稿，不是上线。**要不要上线、站点专有的数字算不算数，都由你定。

## 被 AI 当成事实收录，靠的是这四件事

这四条不是风格建议，每一条都被做成了可量化的机械判据，跑一遍就知道你差多少：

| 原则 | 判据 | 怎么量 |
|---|---|---|
| **多写事实** | W1 事实密度 | 含带单位数值或明确日期的段落，占全部段落的比例。**通过线取对照组中位数**，不是拍脑袋的数字 |
| **引用数据要标来源** | W2 来源标注率 | 有数字的段落里，多少条挂了可点的来源 |
| **证据链要完整** | W3 来源真的打得开 | 每条来源真发一次请求，死链单列。挂死链比不挂更糟 |
| | W4 来源是不是一手 | 域名分档：原始出处 / 新闻转述 / 聚合博客。引自己站的自测数据算一手 |
| | **W5 数字在来源里查得到** | **抓来源页正文，搜这个数字在不在里面。**链接能打开不代表数字对得上 |
| **有图有视频** | W6 可被引的素材 | 图有没有 alt、有没有说明文字、JSON-LD 里有没有 ImageObject 或 VideoObject |

**W5 是这套判据里最狠的一条。**它是证据链上唯一能机器验的最后一环：一条可达、来源又体面、
但数字其实对不上的引用，是最像真的假证据，人工抽查几乎抓不到。

## 通过线为什么取对照组中位数

事实密度写多少才算够？没有任何公开出处能给这个数。所以这里不编：
**抓到 3 个以上对照页时，通过线就是它们的中位数。**你的竞品写到什么密度，你的线就在哪，
出处是那几个页面本身。

抓不到足够对照页时才回退到经验值 0.30，**并且报告里会写明这次用的是回退值**，不假装是实测线。

## 成本，先说清楚

- **零安装**：只用 python3 标准库，不装第三方包，不装 npm，不用浏览器自动化
- **零付费**：不调任何 API
- **会联网**：抓 3 到 5 个对照页，加上核对来源时抓几个来源页，都只读公开页面
- **约 3 分钟**：抓页 1 分钟，写稿与机械闸 2 分钟

## 你要给两样东西

1. **一个目标问题**。你的潜在用户真会拿去搜或去问的那句话。
   从 `rival-teardown` 的选题清单里挑一个最好，自己写一个也行。
2. **一个目标页**。这段内容要贴到哪一页。

对照页不用你准备，skill 自己去抓。

## 五步

```
① 抓对照   winners.py  抓竞品那几页，出写作证据与本次通过线
② 真写     照 references/playbook.md 写，写进 drafts/<日期>-<slug>.md
③ 机械闸   gate.py     出 PASS / REWORK / REJECT，逐项给判据与动作
④ 改内容   针对失分项重写，回 ③。最多 3 轮
⑤ 两个人工确认   机械闸过了也只是没写空，最后两问由人答
```

**第 ④ 步只准改内容，不准改评分器。**判据在 `_shared/rubric.json`，那是三个 skill 共享的单一真相源，
为了让一份草稿过关去动它，等于把尺子锯短。

### ① 抓对照

```bash
python3 <skills>/page-write/scripts/winners.py \
  --question "attachment style test how long" \
  --rivals "https://a.com/x,https://b.com/y,https://c.com/z" \
  --out runs/winners.json
```

有 `rival-teardown` 的产物时更省事：

```bash
python3 <skills>/page-write/scripts/winners.py \
  --question "attachment style test how long" \
  --from-teardown runs/teardown.json --out runs/winners.json
```

产物里有每个对照页的事实密度、结构件（表格 / FAQ / 图 / 视频）、可摘录的事实句，
以及一个 `gaps` 小结：**哪一项对照组一个都没有，那就是缝。**

一个来源都没给时脚本直接报错退出，不去猜对照页是谁。猜错了，后面每条主张挂的证据都是错的。

### ② 真写

照 `assets/draft-skeleton.md` 的骨架写，招式看 `references/playbook.md`。

一条硬顺序：**先结构，后正文。**结构（标题层级、能单独站住的段落、表格、FAQ、JSON-LD）
没到位之前不要先润色句子。理由见 `../_shared/references.md` §1：只改正文，检索命中率是下降的。

草稿必须含一个 ```html 或 ```markdown 的可上线内容块，JSON-LD 写在同一个块里。

### ③ 机械闸

```bash
python3 <skills>/page-write/scripts/gate.py \
  --draft drafts/2026-08-20-attachment-test-how-long.md \
  --question "attachment style test how long" \
  --winners runs/winners.json \
  --self-host 你的域名 \
  --json runs/gate.json
```

`--self-host` 让引自己站的自测数据被算成一手来源。不给的话，你自己的数据会被判成二手，
逼你去找一个其实不存在的外部出处。

退出码：`0` PASS，`1` REWORK（分不够），`2` REJECT（门槛未过）。

加 `--offline` 可以不请求来源页，此时 W3 与 W5 会**记未观察，不判通过也不判失败**。

### ⑤ 两个人工确认（机械闸替不了）

1. **这段里有没有一句是别处抄不到的？**专有数据、机制因果、一手观察算；
   任意竞品页改写一遍就能得到的泛泛描述不算。
2. **AI 真会把这段整段摘走吗？**把最关键那一段单独复制出来，
   它能不能独立回答一个具体问题，有没有找不到先行词的代词。

这两问答不了「是」，草稿就不该上线，哪怕机械闸满分。

## 铁律

1. **不确定就标 `[待核]`，不替站主拍板。**站点专有的功能、数字、算法，没亲自确认过一律标。
2. **每条主张挂证据。**理由那一栏必须挂对照页的原句或 `winners.json` 里的字段，
   不写「建议优化」这种没有出处的话。
3. **未观察不等于零，也不等于通过。**抓不到的对照页不进统计，也不当成「它们没有」；
   没请求到的来源不判可达，也不判死链。
4. **不自动上线、不 push、不改生产分支。**产物只落在 `drafts/` 与 `runs/`。
5. **机械分不许改。**每项都带 `machine_locked: true`，模型只能引用。
6. **主观判断先写理由再写结论。**第 ⑤ 步那两问，先写你凭什么这么答，再答是或否。

## 已知边界（用之前先知道）

- **作者知道判据时，机械闸很容易满分。**它防的是写空，不是证明写得好。真正的判据是第 ⑤ 步那两问。
- **W5 只核数字串是否出现在来源页正文里。**来源页是 PDF 或纯 JS 渲染时会记未观察。
  它也不判断语境对不对：数字对得上但被断章取义，机器看不出来。
- **对照页只给域名不给具体页面时，会退回抓首页。**首页往往不是该对照的那一页，
  提炼出的事实会掺进导航文字。给具体地址。
- **纯 JS 渲染的对照页，抓到 0 词。**那是真实观察（AI 爬虫看到的也是这些），
  但对写作没有参考价值，换一个对照页。
