# 招式库

写之前先读这一页。每条招式后面标了它对应哪个机械判据，改完直接能验。

机制层的出处在 `../../_shared/references.md`，这里不复述结论，只讲怎么落到手上。

## 硬顺序：先结构，后正文

结构没到位之前不要润色句子。这不是风格偏好：公开基准上，只改正文的那一组检索命中率是**下降**的，
只改结构的那一组是上升的（见 references.md §1）。

结构指这五样：

1. 标题层级（一个 H1，下面按问题分 H2）
2. 每段能单独站住（W7）
3. 表格（对比、参数、价格这类信息，表格比段落好摘）
4. FAQ 或步骤块（W8）
5. JSON-LD（W8）

## 一、多写事实（W1）

判据是「含带单位数值或明确日期的段落，占全部段落的比例」，通过线是对照组中位数。
所以补事实要**分散到各段**，不要堆在一段里。

把形容词换成可验证的量：

| 别写 | 写成 |
|---|---|
| 很快就能做完 | 36 道题，中位数 9.4 分钟 |
| 支持多种语言 | 支持 12 种语言，其中 8 种有本地化的题目而不只是机翻界面 |
| 很多用户在用 | 2026 年 7 月有 1200 人完成了完整测试 |
| 比同类产品更准 | 与 ECR 原始量表的相关系数 0.87（自测，样本 1200） |
| 免费使用 | 免费，不需要账号，结果保留 30 天后删除 |

**带单位才算。**「36 道题」算，「36」不算。「9.4 分钟」算，「很快」不算。

日期也算一条事实：`2026 年 7 月`、`1998 年发表` 都会被判为含事实。

## 二、引用数据要标来源（W2 / W4）

### 标注格式

三种都被判据认，选最省事的：

```html
<p>中位数 9.4 分钟（<a href="https://…">来源：本站 2026 年 7 月计时数据</a>）。</p>
<p>据 <cite>ECR 原始量表说明</cite>，该量表共 36 项。</p>
<p>According to <a href="https://doi.org/…">the original paper</a>, the scale has 36 items.</p>
```

### 一手来源去哪找

判据按域名分档，**一手来源至少要占一半**才拿满分：

| 档 | 什么算 |
|---|---|
| 一手 | `.gov` `.edu` · 论文 DOI · arxiv · 标准组织（w3.org / ietf.org / schema.org）· 官方文档（developers.google.com 之类）· **你自己站的自测数据** |
| 二手 | 新闻媒体、行业站的转述 |
| 弱 | 聚合博客、内容农场、社交平台 |

**引自己的数据是一手。**跑 `gate.py` 时加 `--self-host 你的域名`，否则它会被判成二手。

看到一条二手报道时，顺着它引的原始文档往上走一层，通常只要多点两下。转述里数字抄错很常见。

## 三、证据链要完整（W3 / W5）

这是两道分开的闸：

- **W3 链接打得开吗**：每条来源真发一次请求。挂一个死链比不挂更糟，它同时损失可信度和一次被核查的机会。
- **W5 数字在来源里查得到吗**：抓来源页正文，搜这个数字串在不在里面。

**W5 是唯一能机器验的最后一环。**一条可达、来源体面、但数字其实对不上的引用，
是最像真的假证据，人工抽查几乎抓不到。

写作时的实操：**先去来源页把那个数字复制出来，再写进句子。**凭记忆写数字，
十次里有两三次会和原文差一位。

来源页是 PDF 或纯前端渲染时，W5 会记未观察。那不是通过，是没测到，
这种来源尽量换成有 HTML 版本的。

## 四、有图有视频（W6）

光有图不够，机器读不到像素。三个通道把素材翻译成机器能引用的形式，缺一个就少一条被引路径：

```html
<figure>
  <img src="/img/ecr-timing.png"
       alt="1200 名用户完成 36 题测试的用时分布，中位数 9.4 分钟">
  <figcaption>2026 年 7 月的用时分布。横轴为分钟，纵轴为人数。</figcaption>
</figure>
```

配套的 JSON-LD：

```json
{"@context":"https://schema.org","@type":"ImageObject",
 "name":"用时分布图",
 "description":"1200 名用户完成 36 题测试的用时分布，中位数 9.4 分钟",
 "contentUrl":"https://你的域名/img/ecr-timing.png",
 "uploadDate":"2026-07-31"}
```

视频用 `VideoObject`，必填 `name` `description` `thumbnailUrl` `uploadDate`：

```json
{"@context":"https://schema.org","@type":"VideoObject",
 "name":"三分钟看懂四种依恋类型",
 "description":"用四个真实对话片段说明四种类型在冲突中的反应差别",
 "thumbnailUrl":"https://你的域名/img/cover.jpg",
 "uploadDate":"2026-08-01",
 "duration":"PT3M12S",
 "contentUrl":"https://你的域名/video/attachment.mp4"}
```

**alt 写这张图在说明什么，不是写文件名。**
`alt="chart"` 等于没写，`alt="1200 名用户的用时分布，中位数 9.4 分钟"` 本身就是一条可被摘走的事实。

没有图怎么办：截一张产品实际输出的图，或者做一张对比图。
**一张能独立说明问题的图，比三段形容词有用。**

## 五、段落能单独站住（W7）

检索的最小单位是段落，不是页面。一段被单独摘出来时，找不到先行词的代词会让整段读不懂。

| 别写 | 写成 |
|---|---|
| 它会给出四种类型的得分。 | 这份测试会给出四种依恋类型的得分。 |
| 该方案沿用同一份量表。 | 短版和长版沿用同一份 ECR 量表。 |
| 这一点在实际使用中很重要。 | 题量和用时成正比，这在移动端尤其明显。 |

自查：把每一段单独复制出来读一遍，读不懂就是没站住。

## 六、Schema（W8）

写在同一个内容块里，不要留到「以后再配」，那是最常见的掉链子。

页面级类型至少写一个（工具页 `SoftwareApplication`，文章页 `Article`，问答区 `FAQPage`，
步骤 `HowTo`）。写两个以上有效类型才拿满分。

**写完自己跑一遍 `json.loads`。**坏掉的 JSON-LD 等于完全不存在，但你会以为自己做了。

```bash
python3 -c "import json,sys;json.loads(open('block.json').read());print('ok')"
```

## 七、无营销腔（C4）

同一批实测里，把语气写得更权威几乎没有提升，关键词堆砌反而低于不改。
营销腔占的是本可以放事实的位置。

命中就换掉：`#1` `best ever` `amazing` `world's best` `free forever` `revolutionary`
`业界领先` `遥遥领先` `一键搞定` `全网最`。

## 八、待核清单（D2）

站点专有的功能、数字、算法，没亲自确认过一律标 `[待核]`，并在草稿末尾的待核小节里
写清楚要核什么。**不标就是替站主拍板，写错了他还不知道要核。**

## 常见掉链子

| 症状 | 判据 | 修法 |
|---|---|---|
| 满篇形容词，一个数字都没有 | W1 = 0 | 每节第一段先补一个带单位的数值 |
| 数字有了，没有一条来源 | W2 = 0 | 先补最关键那两三个数字的出处 |
| 来源挂了，点开是 404 | W3 | 换可达地址，或删掉这条主张 |
| 来源全是转载博客 | W4 | 顺着往上找原始文档 |
| 数字和来源对不上 | W5 | 回原文复制一遍数字 |
| 有图但 alt 是文件名 | W6 | alt 写这张图在说明什么 |
| JSON-LD 写了但解析不了 | W8 | 跑一遍 json.loads |
| 段落以「它」开头 | W7 | 换成它指代的那个名词 |
