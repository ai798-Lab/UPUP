## 1. AI 爬虫 UA 四分类

**核心纠偏：抓取权限分档报告，不合并成一个「AI 可访问性」分。**
放行训练 bot 不等于能被搜索引用；放行只是可访问条件，不保证索引、服务或引用。

| 平台 | AI 检索索引 | AI 实时取页 | 训练 |
|---|---|---|---|
| OpenAI | `OAI-SearchBot` | `ChatGPT-User` | `GPTBot` |
| Anthropic | `Claude-SearchBot` | `Claude-User` | `ClaudeBot` |
| Perplexity | `PerplexityBot` | `Perplexity-User` | 无独立训练 bot 声明 |
| Google | `Googlebot`（AI features 仍由它控制，无独立 AI bot） | 同左 | `Google-Extended` 控制训练与 grounding 使用 |

传统检索单列一档（`Googlebot` / `Bingbot`），所以本套件用的是**四档**而不是三档：
`search` / `ai_search` / `ai_user` / `training`。分四档的理由是后果不同：

- `ai_search` 被挡 = AI 的索引里没有你
- `ai_user` 被挡 = **AI 当场想引你都取不到页面**，写得再好也没用

**训练档拦不拦是站主的选择。**屏蔽 `GPTBot` / `ClaudeBot` / `Google-Extended` 不影响搜索可见性，
所以本套件只报事实，不判对错。

Perplexity 还有 WAF 与 IP 校验层，**放行 UA 不等于放行请求**。这是 `robots.py` 里
robots 判定和 UA 实探分开报的原因。

出处：OpenAI / Anthropic / Google / Perplexity 各自的官方 crawler 文档。
**核实日期 2026-07-21**，标记 volatile。用前对官方文档复核。

## 2. 改写手法的实测效果排序

**核实日期 2026-08-20。**出处：GEO: Generative Engine Optimization，Aggarwal 等，
KDD 2024，arXiv:2311.09735。测试台是自建的模仿 Bing Chat 的引擎，跑 GEO-bench
（10000 条 query，8 个领域）。

论文表 1 报的是 Position-Adjusted Word Count 这一可见度指标，baseline 19.3：

| 手法 | 分数 | 相对 baseline |
|---|---|---|
| Quotation Addition 加可归属引语 | 27.2 | 明显提升 |
| Statistics Addition 加统计数字 | 25.2 | 明显提升 |
| Fluency Optimization 通顺度 | 24.7 | 明显提升 |
| Cite Sources 标注来源 | 24.6 | 明显提升 |
| Authoritative 写得更权威 | 21.3 | 无显著提升 |
| Keyword Stuffing 关键词堆砌 | 17.7 | **低于 baseline** |

**这条结论的边界必须一起记住**：论文的实验设计是固定把 top-5 文档喂进生成器，
只测「已经在上下文里的文档如何被更多引用」。**它没有证明可发现性，也没测下游流量。**
所以它支撑的是「内容怎么写」，不能拿来支撑「能不能被检索到」。

另有同行评审论文（C-SEO Bench）在部分手法上得出相反结论。
**这个领域不存在「最新的就是对的」，只存在「有没有对照组、有没有跨引擎复现」。**

**本节支撑的判据**：W1 事实密度、W2 来源标注率、C3 可提取证据密度、C4 无营销腔。
这四项在 `rubric.json` 里标 `Research`。

## 3. 抽取友好的内容启发式（不是平台规则）

「前 50 词答案前置」「段落能脱离上下文单独成立」「问句式 H2」都是
**可读性与抽取友好的启发式，不是已证实的统一排名规则**。

验证目标应该是「答案直接、段落单独摘出来仍然成立」，
**不以词数是否达标当通过条件**。写进判据时当可配置的启发式，别写成平台硬规律。

多模态（关键图 alt、视频 transcript）同理：有益，非保证。

出处：本套件与其前身的实践判断，**没有平台文档或对照实验支撑**。
**本节支撑的判据**：WG1 答案前置、C2 首屏给答案、W7 段落能单独站住、W6 素材。
这几项在 `rubric.json` 里标 `Heuristic` 或 `Official`（W6 的 schema 部分有 schema.org 出处），
**都不标 Research**。

## 4. 结构与正文孰先（出处待补）

有一条在这条工作线里被反复引用的主张：**只改正文，检索命中率会下降；只改结构，会上升。**
转述的数字是「17 万篇文档的公开基准实测，只改正文下降 9%，加技术术语下降 14%，只改结构上升 22%」。

**这条目前没有可点的原始出处。**数字来自项目内部转述，本台账没有核实过论文或基准的原文。

所以：

- **不作为 Research 级依据使用。**任何判据都不许把 source 指向本节来给自己撑腰。
- 「先结构后正文」这条操作顺序**仍然写在 playbook 里**，因为它同时被 §2 支撑
  （§2 里效果最好的三种手法，加引语、加统计数字、标注来源，都需要先有可放它们的结构位）。
  但 playbook 里引用的是 §2，不是本节。
- 补上出处之前，本节只当作**待验证的工作假设**存在。

**要补的东西**：那份基准的名字、发表处、样本构成、对照组设计。补上之前不要在对外材料里
把这三个百分比当成实测结论引用。

## 5. llms.txt 的真实定位

**降级为低成本可选元数据，不计核心分。** Google 明确 AI features 不需要新的机器可读文件
或特殊 markup；主流平台未把 llms.txt 声明为排名或引用因子。

另有一组公开日志数据（13.7 万域名）显示：约 28% 的域名发布了 llms.txt，
其中约 97% 从未收到过对该文件的请求。**这组数字同样是转述，本台账未核实原始数据源，
标记为待核。**

本套件**不检查 llms.txt**，也不建议你花时间做它。

出处：Google「AI features and your website」。核实日期 2026-07-21，volatile。

## 6. 结构化数据的真实定位

- **结构化数据应匹配页面可见事实。没有平台证据证明特定 Schema 组合能「保证」生成式引用。**
- 判据只检查「是否准确表达该页实体与事实」，不按 Schema 数量或固定类型给满分。
- `AggregateRating` 只在真有评价体系时才该写，**凭空塞会被忽略甚至处罚**。
  本套件检测到页面自己给自己写评分时会标为需要人核，但**不直接判 0 分**，
  因为有真实用户评价的产品页写它是合法的。
- 结构化数据与页面可见内容不一致是明令的违规项，这一条有官方文档支撑。

出处：Google 结构化数据通用指南 + schema.org。核实日期 2026-07-21，volatile。
**本节支撑的判据**：T7 / T8 / T9 / W8，标 `Official`。

## 7. Google 的官方立场

Google 的公开说法是：**为 AI 搜索做的优化，就是为搜索做的优化。**
没有独立的一套「AI SEO」规则，传统排名仍然是准入门槛。

这也是本套件把 SEO 与 GEO 放在同一次体检里查的原因：
四项技术基建（sitemap / robots / canonical / 结构化数据）两侧共用，
只是两侧关心的后果不同。

出处：Google「AI features and your website」。核实日期 2026-07-21，volatile。
