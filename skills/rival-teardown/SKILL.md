# rival-teardown · 拆竞品，产出该写什么

它回答两个问题：

1. **对手靠哪些词拿量**：跨页统计标题里的实义词。一个词被多页覆盖，说明他们在系统性地做它，
   不是随手写了一篇。只在一页出现的词是噪声，不进清单。
2. **你缺哪几样**：把对手覆盖的词和你自己站的做差集，得到选题清单。

**它是 `page-write` 的上游。**「该写什么」的答案从这里来，写出来交给 `page-write`。

## 什么时候用它

| 你会这么说 | 就是这个 skill |
|---|---|
| 竞品靠什么赢的 / 拆一下这几家 | 是 |
| 我接下来该写什么 / 给我选题 | 是 |
| 他们那一页怎么写的 | 是 |
| 我的站技术上有没有问题 | 不是，用 site-audit |
| 帮我把这个题目写出来 | 不是，用 page-write |

## 成本

- **零安装零付费**：只用 python3 标准库
- **会联网**：每家抓 sitemap 加最多 12 个页面，只读公开页面
- **2 到 4 分钟**：拆 3 家的话到 5 分钟

## 怎么跑

```bash
python3 <skills>/rival-teardown/scripts/teardown.py "a.com,b.com" \
  --mine 你的域名 --json runs/teardown.json
```

**`--mine` 不给的话，「你缺什么」那一栏是空的**，只能告诉你对手在做什么。
第一次跑就把它带上，多花一分钟。

产物直接喂给 `page-write`：

```bash
python3 <skills>/page-write/scripts/winners.py \
  --question "<从清单里挑一个>" --from-teardown runs/teardown.json --out runs/winners.json
```

## 选题清单里每条带什么

| 字段 | 意思 |
|---|---|
| `topic` | 这个词 |
| `rival_pages` | 对手有几页在做它。数字越大，说明他们越当回事 |
| `page` | **对手在这个词上写得最好的那一页地址**。你自己去打开看 |
| `why_it_works` | 那页凭什么：事实密度多少、有没有对比表、有几段挂了外部来源、有没有 FAQ 或步骤结构化数据 |
| `you_lack` | 你现在缺哪几样。只列机器看得出来的差距，不替你判断内容好坏 |

**每条选题都挂着对手的页面地址。**没有出处的选题不产出，因为你没法自己去核。

## 三条纪律

1. **抓不到的页记未观察，不进任何统计，也不当成「他们没有」。**被防护规则拦住的页会单独列出来，
   报告里会告诉你有几页没抓到。
2. **只报机器看得出来的差距。**「他们的文案更打动人」这种判断这里不产出，
   因为它没法复核，你也没法照着改。
3. **不硬凑选题。**过滤掉三类噪声：对手的品牌名（你抢不走）、语言代码（多语言站到处都是）、
   计量碎片（从「9 min」里切出来的 min）。过滤完可能只剩两三条，**那就是真实情况**。

## 已知边界（用之前先知道）

- **每家只抓 12 页，等距取样。**结论只覆盖抓到的这些页，不是全站结论。
  用 `--limit` 可以调，但抓得越多越慢。
- **给不同类的站当竞品，清单会很短甚至为空。**那是对的，不是坏了：
  两个不相关的站本来就没有共同可争的词。清单短的时候先检查竞品选得对不对。
- **词覆盖用的是标题和 H1，不是正文。**标题是他们主动声明「这页在做什么」的地方，
  信号最干净，但也意味着标题写得随意的站会被低估。
- **它不告诉你这个词有多少搜索量。**免费拿不到可信的搜索量数据，这里不编。
  `rival_pages` 是替代信号：对手押了几页在这个词上。
- **不跑 JS。**纯前端渲染的竞品页会抓到 0 词，那家的结论不成立，报告里会标出来。
